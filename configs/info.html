osmo-operator - running the bench

A complete 2G network with no radio hardware (emulated Calypso baseband, Osmocom core, gr-gsm layer 1), a 4G cell (srsRAN + Open5GS), a SIP softphone and a postmarketOS phone VM. Everything lives in /opt/GSM/osmo-operator. For each module this page gives the three ways to start it: dock icon launcher bar CLI, and the file in the repository that does the work.

Three rules. The bench runs as root: icons use pkexec (a password window), the CLI wants sudo. Long-running parts are systemd units, so systemctl and journalctl know them. Nothing 2G or 4G starts at boot: starting the bench is your gesture (see iso_modules/00-options.sh).

GSM bench Lancer le banc GSM run standalone CLI

The red phone icon runs launch.sh: Wireshark on GSMTAP (udp/4729), Linphone, Firefox on the dashboard, then start-direct.sh, the native single-operator bench (hlr, msc, bsc, stp, mgw, bts-trx, the emulated mobile with QEMU + trxcon, gapk voice). The launcher bar's run standalone starts osmo-banc.service without any terminal and streams its journal in the bar (click journal to expand).

Multi-operator SS7 multi-operator run multi CLI

Operator 1 stays native (point code 1.1.2). Operators 2 and 3 are the containers osmo-operator-2 and osmo-operator-3 (172.20.0.12 / .13, PC 1.2.2 / 1.3.2) and the hub is osmo-inter-stp (172.20.0.10, M3UA over SCTP 2908). The antenna icon runs launch.sh --multi, which starts osmo-multi.service; the unit runs start-multi.sh, which reads the topology written by the Supplements (/etc/osmocom/osmo-multi.conf) and delegates to start.sh virtual --operators 2 with OP_ID_BASE=2.

systemctl start osmo-multi          # a session (several minutes: images, containers, HLR)
journalctl -u osmo-multi -f         # follow it
sudo ./start-multi.sh --status      # containers and hub
systemctl stop osmo-multi           # remove the containers (the native op stays)
systemctl enable --now osmo-multi   # every boot (off by default)

Dialling plan: MSISDN = <node>00<op><ms> (100101 = node 1, op 1, MS 1); the prefix to reach another node is its indicatif (11, 22, 33; iso_modules/00-options.sh). The SS7 matrix comes from checks/ss7_check.sh.

Supplements Supplements CLI

The Supplements icon runs addition.sh with a checklist. It installs what is not in the ISO. With multi-operator ticked it installs docker, pulls the operator image (ghcr.io/bbaranoff/osmo-operator/osmocom-nitb), derives osmocom-run (Dockerfile.run), writes the topology, installs osmo-multi.service and the antenna icon, then starts the multi bench once so the containers exist when the window closes (OSMO_MULTI_START=0 to skip).

sudo ./addition.sh             # checklist window
sudo ./addition.sh --multi     # docker + image + topology + start
sudo ./addition.sh --opencl    # OpenCL runtime and GPU driver
sudo ./addition.sh --claude    # Claude Code CLI
sudo ./addition.sh --extras    # Doom, Quake III, Kodi, YouTube, Wireshark (root), Linphone
sudo ./addition.sh --status    # what is present

At boot an encrypted /home asks for its passphrase, echoed as **** (configs/crypthome/unlock-home): typing it opens the user session, pressing Enter on an empty line, or not answering, opens an ephemeral root session; the boot never blocks.

The launcher bar and the desktop widgets

The bar at the bottom (tools/osmo-launcher.py) groups Banc, Jeux, Media, Telephone and Outils. The three run buttons never open a terminal: they run in the background (as root through pkexec), write to $XDG_RUNTIME_DIR/osmo-launcher/<name>.log, and the bar unfolds a live log pane (one tab per run, stop and fold buttons). Other buttons: click = fit on the live frame, the fullscreen button, the send-to-top button (LAB GSM zone).

The live frame (tools/osmo-fft-snap.py) shows the bench illustration, fading to the I/Q spectrum and mobile.log when the bench runs; the banner (tools/osmo-topzone.py + configs/conky/labgsm.html, fed by tools/osmo-ts-probe.py) shows the eight timeslots, core and radio daemons, subscribers, calls and uptime in real time; the Conky (configs/conky/osmo-conky.conf) shows the machine and the selected operator (Ctrl+AltGr+Left/Right, or osmo-op --next).
